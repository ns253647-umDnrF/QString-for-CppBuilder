# Проверка релиза 2026.11.11

## Автономный набор в архиве

`python tests/run_tests.py` выполняет четыре профиля: Win32/Win64 × default/O2.
Тесты запускаются из исходников и не используют установку Qt или сеть.

В каждом профиле выполняются:

- четыре базовых программы строковых и символьных регрессий;
- отдельные регрессии printf-форматтера и сборка примера;
- четыре проверки компиляции QChar/QCharRef/64-битных чисел;
- значения перечислений в C++11 и C++14, компиляция и запуск стандартных форм API;
- 126 596 сценариев прямого/обратного поиска, count, startsWith, endsWith и split;
- 74 772 сценария contains/indexOf и toInt с разными основаниями;
- 54 725 проверок QCharRef, включая расширение, NUL, разделяемые копии и недопустимые индексы;
- 269 232 проверки local8Bit при четырёх настройках Delphi RTL (на Windows ACP 1251);
- 33 680 числовых проверок: кратчайшая запись double, number/asprintf, toDouble/toFloat,
  четыре режима округления FPU;
- 84 692 проверки многомодульной интеграции, контейнеров и независимых копий в восьми потоках;
- сценарии производительности поиска и подсчёта перекрывающихся совпадений.

Числа выше относятся к проверкам конкретных наборов, а не к числу разных исходных
строк. Например, один сценарий QCharRef проверяет несколько состояний строки.
Точные суммы и пропуски записываются в `results.json` каждого запуска.

## Запуск и результаты

```bat
python tests\run_tests.py --arch win32 --opt O2
python tests\run_tests.py --arch win64 --opt default
python tests\run_tests.py --strict-performance --require-acp1251
```

`--compiler32` и `--compiler64` позволяют указать пути к компиляторам.
Можно использовать `--build-dir "D:\test output\new run"`: каталог должен
быть новым. По умолчанию каждый запуск создаёт отдельную папку в `tests/build/`.
В ней остаются `results.json`, `build.log`, программы, объектные файлы и результаты
сравнения. Эти файлы не являются частью поставки.

Проверки времени по умолчанию измеряют длительность и проверяют правильность
результата. `--strict-performance` дополнительно включает широкие пределы для O2:
100 мс для длинного поиска/подсчёта и 5 мс для раннего совпадения/старта возле конца.
Эти пределы зависят от производительности и нагрузки машины.

На системной ACP, отличной от 1251, набор `local8bit` явно пропускается;
остальные наборы продолжают работу. `--require-acp1251` запрещает такой пропуск.
Ни тесты, ни адаптер не меняют системную ACP Windows.

## Эталонные данные

`tests/fixtures/*.bin.gz` — постоянные тестовые данные, а не временные продукты
сборки. Входные данные и ожидаемые результаты сохраняются раздельно. При запуске
ожидания не вычисляются адаптером и сравнение проводится побайтово.

Эталоны для поиска, целочисленного и вещественного разбора, форматтера и local8Bit
заново получены из нативной DLL Qt 5.15.2 Win64. Один и тот же эталон используется
для обеих архитектур адаптера. Ожидания QCharRef построены по исходнику Qt 5.15.2
`qstring.h` (преобразование/присваивание QCharRef); это отдельная модель, а не результат
адаптера. Привязка к версии Qt, исходникам и контрольные суммы есть в
`tests/fixtures/corpus.json` и `docs/release_provenance.json`.

В данных присутствуют null/empty, встроенный NUL, корректные и непарные суррогаты,
обе чувствительности к регистру, перекрытия, граничные позиции, длинные повторяющиеся
шаблоны и воспроизводимая случайная выборка. Заведомо небезопасные позиции, на которых
оригинальный Qt может читать до буфера, исключены из вызовов эталонной DLL.

## Полный рабочий аудит и пакетный набор

Автономный набор в архиве — выделенный набор для пользователей пакета.
Он не является копией всех 58 исторических сценариев разработки, часть которых
требовала старых дефектных версий, исходников Qt и локального эталонного окружения.
Итог полного аудита до оформления версии сохранён в `docs/full_audit_58.json`;
в архив не включены его временные файлы, бинарные зависимости, рабочие резервные
копии и диагностические журналы.

Новая версия отличается от версии полного аудита только комментариями версии
в трёх заголовках. Побайтовая проверка этого ограничения и старые/новые SHA-256
находятся в `docs/release_provenance.json`. Сам пакет дополнительно собран и
проверен после распаковки; результат — `docs/package_test_results.json`.

## Непроверенные конфигурации

Классический bcc32, другие версии компиляторов/ОС и другие системные ACP не входят
в подтверждённую матрицу. Полный рабочий аудит включал guard pages, несколько
локалей и режимов точности FPU; он не является полным heap-sanitizer или кампанией
внедрения отказов выделения памяти. Не заявляется проверка всех возможных настроек
floating-point traps, FTZ/DAZ и пользовательских кодеков Qt.
